# SouthGrid 本机执行说明（`codex/pico-task3-monitor`）

当前工作区已切到：

- 远程：https://github.com/Pawis185/SouthGrid
- 分支：`codex/pico-task3-monitor`（`d839d78`）

本文只写**本机怎么跑**。设计细节见 `docs/pico_task3_monitor.md`。

## 1. 环境

```bash
source ~/.bashrc
conda activate orcalab_lerobot
cd /home/hello/workspace/SouthGrid
python scripts/verify_environment.py
```

也可用：

```bash
source /home/hello/workspace/SouthGrid/.activate_conda.sh
```

应看到：`Environment verification OK`。Python 必须是 `~/miniconda3/envs/orcalab_lerobot` 下的 3.12.13。

首次使用前启动 OrcaLab，并订阅资产：

```bash
orcalab
```

- `SouthGrid_Competition_2026`
- `g1_omnipicker`
- `g1_pick`

订阅后关掉再开一次 OrcaLab，等资产同步。

## 2. 加载任务三场景并配相机

1. 在 OrcaLab 加载布局：`src/examples/dataCollection/g1_omnipicker/g1_tool.json`
2. 配两路相机后再统一勾选 Recording：

| 位置 | 布局实体 | 代码名 | Color Port |
|------|----------|--------|------------|
| 头部 | `camera_head` | `camera_head_color` | 7090 |
| 右腕 | `camera_right` | `camera_wrist_r_color` | 7080 |

每路勾选：UseNvEnc、Color Camera；两路都配完后勾选 IsRecording。

3. 点运行，等仿真起来。gRPC 默认 `localhost:50051`。

## 3. Pico 遥操作（任务三监控采集）

需要本机已装 `adb`（若没有：`sudo apt install adb`），Pico 已按官方 VR 遥操作指南连好。

```bash
conda activate orcalab_lerobot
cd /home/hello/workspace/SouthGrid/src/examples/dataCollection/g1_omnipicker
adb reverse tcp:8001 tcp:8001
python g1_omnipicker_collection_tele_lerobot.py \
  --task_config ../common/example.yaml \
  --lerobot_out ~/datasets/g1_tele \
  --repo_id local/g1_omnipicker \
  --task 整理工具 \
  --fps 20 --clock wall \
  --cameras head,wrist_r --cam_resolution 480x640 \
  --camera_source websocket --task3_monitor
```

续采加 `--resume`。端口冲突加 `--task3_monitor_port 8767`。

默认每成功保存一集后按 5 件工具全排列换货架顺序（120 套）；丢弃/删除重试当前套。满 120 集结束。关闭换序：`--tool_layout_cycle 0`。查表见第 4 节「查表：120 套工具顺序」。

**不要**同时用 `mp4` 相机源和 `--task3_monitor`，脚本会直接报错。

不加 `--task3_monitor` 则走原来的采集流程，不开日志和监控页。

### 手柄

| 操作 | 按键 |
|------|------|
| 开始本集 | 左 Grip 按一次 |
| 结束本集 | 再按一次左 Grip |
| 分类保存 | 松开后：左 Grip=好，X=合格，A=存疑，右 Grip=删除 |
| 录制中放弃 | 右 Grip |
| 结束全部采集 | 左右 Grip 同时按 |

本入口默认不控底盘。监控页上能看到 reach 区域，不代表能把底盘开到作业位。

### 监控页

浏览器打开：http://127.0.0.1:8766/

只监听本机。画面是世界坐标俯视/侧视示意，不是相机画面。Pico 头显里没有这条页面，需要能看到主机屏幕。

显示的是本地规则分（总分 /40，reach /5，五件工具各 /7），**不是**排行榜成绩，也不会创建 ScorerClient attempt。

## 4. 输出目录

```text
~/datasets/g1_tele/
  good/ | qualified/ | Doubtful/     分类后的 LeRobot 数据
  scene_sidecar/                     仅 --task3_monitor 时写入
    episodes/<UUID>/
      raw.jsonl                      原始物理/控制/相机记录
      scene.mjb
      score_latest.json
      review.json
```

分类写入不会覆盖已有 `good/qualified/Doubtful` 数据，按类别追加。场景日志用 UUID，不复用 episode 编号。

**120 套摆放不会各建目录。** 训练数据仍按质量合进 `good/`、`qualified/`、`Doubtful/`。第几套看三个分类**合计**成功保存数（删除/丢弃不算）。开了 `--task3_monitor` 时，该集 sidecar 的 `reset_completed` 也会写当前左→右顺序。

## 5. 不带 Pico 的脚本化采集（对照）

```bash
conda activate orcalab_lerobot

  --task_config ../common/example.yaml \
```

## 6. 正式评分（与监控页无关）

监控页不算官方成绩。要上报排行榜，需在本机跑 ScorerClient（已装在 `orcalab_lerobot`），凭证写在：

`~/.config/orca_scoring/orca_scoring.yaml`

把占位的 `team_id` / `team_token` 换成大赛发给本队的值。ScorerClient 必须和 OrcaLab 在同一台机器。

## 7. 已知限制

- 该分支尚未做真实 ORCA + Pico + 双相机端到端验收。
- 监控分不含官方 attempt 末尾的确定性 jitter，不能当榜上分数。
- 本机若还没装 `adb`，遥操作前需要先 `sudo apt install adb`。
